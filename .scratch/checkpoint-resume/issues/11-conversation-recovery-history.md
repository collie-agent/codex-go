# 11: 新任务和 resume 按状态加载会话历史

**What to build:** 用户在同会话开启新任务或恢复运行时获得此前运行的适当历史；中断后的任务能理解此前工作，且不会把旧目标当成待继续调度的任务。

**Blocked by:** 09 — CLI 主动中断整个运行

**Status:** ready-for-agent

- [ ] 按此前运行顺序加载 completed 的 result/error、failed 的 error；pending/running 的其他运行不作为已结束历史，当前 run 不重复加入。
- [ ] interrupted 历史包含原目标、完成标准、实例归属、子任务目标与标准、已保存结果及完整工具交互，并按计划步骤或委派关系组织。
- [ ] 以前序运行历史参考表达旧任务，明确当前输入决定新目标；已确认工具交互转为 system 之后的原生调用/结果消息，未知结果保留参考文本，不伪造工具返回，也不恢复旧任务调度。
- [ ] resume 另外加载当前运行持久化状态，当前运行仅恢复当前执行实例工具交互，当前运行其他步骤或 worker 的交互不混入该实例。
- [ ] 新任务与 resume 共用历史组装规则，各 run 只保存自身产生内容，连续中断及新任务不会递归复制继承历史。
- [ ] 所有符合条件的历史完整加载，不自动摘要或截断；上下文超限明确报错。failed 未知结果错误保留调用 ID、名称及参数。
- [ ] 端到端验证普通 ReAct、计划和多代理中断后新输入创建新 run 并继承组织化历史；验证 resume、混合状态过滤、多次中断及上下文超限。
- [ ] 更新会话历史说明，不增加旧数据兼容、配置变化兼容性或预算恢复逻辑。
