# 05: 普通 ReAct 持久化与恢复

**What to build:** 用户通过现有 CLI 或服务入口恢复普通 ReAct，延续原执行实例及已确认工具交互；结果未知时停止，已有最终结果直接返回。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 新运行持久化原目标、完成标准、run_id、执行模式及工作目录；为独立 ReAct 上下文建立稳定 execution_id，恢复保留身份，普通模式不产生计划步骤。
- [x] 通过显式迁移命令建立执行实例及共享 tool_execution 记录，保留根 run_id、execution_id、调用 ID、名称、原始参数、批次与批内顺序、状态、结果和错误；沿用命名及时间字段约定。
- [x] 在共享 ReAct 执行路径中，工具执行前原子登记整批调用；各工具结果分别提交，下一轮模型只使用已确认结果。持久化失败停止后续调度。
- [x] 正常执行和恢复均保留当前实例完整工具历史，按模型调用顺序组装原生消息，移除自动移出部分工具结果的行为；并发完成顺序不改变上下文顺序。
- [x] 模型请求期间尚未保存调用时重新请求；已保存结果不重复执行；已登记但结果缺失时不启动模型或工具绕过未知状态，错误包含调用 ID、名称与参数。
- [x] 保存完整结构化实例结果与运行终态；区分终态业务失败和执行故障。已有成功或终态业务失败结果直接返回，未收尾时复用结果完成收尾；可恢复故障继续原实例。
- [x] 沿用根运行连接锁，所有执行检查点使用持锁连接；锁失效或写入失败停止调度，不能换连接绕过互斥。
- [x] 故障注入覆盖整批登记失败、执行产生副作用但结果未保存、部分结果提交、结果全部提交、最终结果已保存但尚未收尾；断言工具调用次数和恢复消息内容。
- [x] 验证 CLI/服务恢复入口、实际数据库锁竞争及迁移可重复执行；更新普通 ReAct 恢复说明，确保纯 MCP 路径不受影响。
- [x] 本任务不实现会话历史扩展、计划或多代理调度恢复；不增加旧数据兼容、配置变化兼容性或预算持久化。

## Comments
