# 10: 服务端按 run_id 主动中断

**What to build:** 用户通过服务端显式请求中断指定根 run_id，由实际执行者停止整个运行并保存中断状态。

**Blocked by:** 09 — CLI 主动中断整个运行

**Status:** ready-for-agent

- [ ] 提供按根 run_id 显式中断的服务接口，覆盖服务实际支持的执行路径；中断信号送达真正持有运行锁的执行者，不能仅修改数据库状态伪造停止。
- [ ] 复用统一中断流程，三种模式均停止新调度、取消子任务并保存可确认结果；不单独中断 worker。
- [ ] 中断请求不争抢执行者长期持有的运行锁造成死锁，也不越过执行者直接改写执行检查点。
- [ ] 区分中断请求已接收和中断已完成；不存在的 run、已终止 run、重复请求及无法送达执行者的请求有明确响应，不虚报中断成功。
- [ ] 请求断开不视为主动中断；中断与终态写入并发时遵守任务 09 的终态规则。
- [ ] 通过服务请求与实际执行者的集成测试验证并发工具、计划、多代理中断，断言状态、结果保留、无后续调度及锁正常释放；按实际部署路径覆盖跨执行进程信号传递。
- [ ] 更新接口使用说明，记录中断响应含义及 interrupted 不可 resume 的行为。
