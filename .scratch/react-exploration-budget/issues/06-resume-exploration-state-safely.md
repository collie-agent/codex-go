# 06: 中断恢复后继续原预算与阶段

**What to build:** 普通 ReAct 在进程故障或可恢复失败后继续原执行实例，延续探索预算、阶段与可信修改证据；保存失败、崩溃窗口和旧检查点均不能造成额度刷新或不安全的工具重放。本票补齐跨持久化边界的恢复行为，不替代前序票的基本状态保存。

**Blocked by:** 05：首次修改后的持续预算约束。

**Status:** ready-for-agent

- [x] 从未分类、阈值决策、已批延期、待首次修改、待后续修改及验证状态恢复，保留原任务类型、有效策略、探索消耗、额度、延期次数、纠错消耗、窗口余量和交接证据。
- [x] 恢复不因配置文件改变重新授予额度，新执行实例独立初始化；用户主动中断结束原运行，不混同于原实例的恢复。
- [x] 使用应用公开恢复边界与真实检查点序列化验证状态往返，不能仅验证内存对象复制；持久化失败必须阻止后续模型决策或工具放行。
- [x] 覆盖决策已扣费尚未请求模型、延期已保存尚未执行、工具结果已保存而阶段证据尚未保存等崩溃窗口；补偿处理不得重复授予额度或重复计费已确认的同一操作。
- [x] 工具执行前登记、执行后保存结果的顺序保持不变；工具结果未知时遵循 ADR-0004，停止自动执行，不借恢复重跑。
- [x] 旧检查点缺少新字段时采用明确兼容处理，不能伪造已修改状态或刷新已知消耗；无法确认的历史保持未知，并有相应测试。
- [x] 总预算和现有停滞机制优先，仍预留有界失败收尾；收尾请求失败或曾经开始后恢复，不无限重复总结，不编造成功。
- [x] 失败保留已确认变更、验证结果、未完成项和停止原因，不自动回滚；恢复日志能说明采用的原策略与剩余状态。
- [x] 通过跨多次恢复端到端测试证明预算和窗口不刷新、延期不重复、未知工具不重放，并验证恢复后能继续真实修改、验证和完成。


## Comments

- 使用用户确认的两个测试边界：`application.Resume` + 真实 MySQL 检查点序列化，以及 `ReactProcess.Run` + `SetCheckpoint` 故障注入。逐条执行 red → green，保留现有工作区前序票实现。
- 最后一个并行工具结果保存时，同一检查点保存批次目标快照；阶段确认使用交接编号和 `Applied` 标志补偿。恢复只使用已保存的操作前后证据，不把恢复时的工作区当作历史快照，不重复计费或刷新窗口。已退出进程的已保存跨批次证据可以补偿，旧进程身份仍不继承。
- 恢复在调度模型前检查已耗尽的纠错额度、已保存的无法完成决策和已开始的失败收尾。阶段拒绝原因随纠错状态保存；原策略及剩余探索、总预算和窗口写入恢复日志。失败结果保留已确认目标变化、验证记录、未完成条件和停止原因，拒绝总结中的工具与成功声明，不回滚文件。
- 旧检查点首次补建探索状态时，使用当前有效策略并保守继承已有总决策消耗；缺少总计数时，以已有工具批次数作为已知消耗下界。缺少操作后快照或交接归属的历史不伪造修改证据；未知工具结果继续遵循 ADR-0004，在任何模型或工具执行前停止。
- 应用集成覆盖未分类、阈值纠错、已批延期、首次／后续修改和验证状态往返，配置改变、主动中断与新执行实例隔离，旧检查点和未知结果。连续五次恢复端到端覆盖调查、延期、空补丁消耗窗口、实际修改、真实 `go test` 成功和完成，验证累计预算、延期与窗口不刷新。
- 沿用并运行前序票的决策预扣费、保存失败、总预算和停滞恢复回归；新增结果已保存而阶段保存失败、纠错耗尽、无法完成、收尾中恢复及缺失历史快照的公开边界测试。
- 验证：`go test ./...` 全仓通过，使用独立测试库实际执行 MySQL 和 CLI 集成测试；恢复、并行批次与进程修改基准相关的定向 `go test -race ./internal/agent` 通过；`git diff --check` 通过。测试账号初始认证／权限问题已通过独立测试账号解决，测试结束已撤销临时 SUPER 和临时建库权限，未改动项目数据库配置。
