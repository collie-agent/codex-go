# 02: 实施交接到真实补丁修改

**What to build:** 普通 ReAct 在证据充分时通过实施交接进入有界修改窗口，通过补丁取得可确认的目标变更，再验证并完成任务；交接声明和补丁成功本身均不冒充实际修改。

**Blocked by:** 01：探索阈值、延后分类与阶段决策。

**Status:** ready-for-agent

- [x] 支持阈值处或证据充分时提前实施交接，必须明确目标文件及预期变更、已有证据和下一项操作；校验并保存后才能继续执行。
- [x] 修改窗口默认三个业务决策轮，可在配置文件设置并逐字段继承；仅接受正整数，省略采用默认值，阶段决策及纠错不占窗口。
- [x] 窗口内允许必要定位与补丁纠错，但调查仍需剩余探索额度；探索耗尽时须利用已有证据直接修改，不能借窗口免费调查。延期支持接入 03。
- [x] 对目标文件在补丁执行前后的存在状态和内容进行比较，支持新增、修改与删除，不依赖 Git 或干净工作目录。
- [x] 空补丁、相同内容覆盖、相互抵消的补丁和既有未提交改动不算本次修改；修改无关文件不满足目标变更条件。
- [x] 部分失败时只采用可确认的实际变化；只有受影响路径、工具成功或模型声明时不能推断发生目标修改。未知变化不算已修改。
- [x] 同一待实施修改不能通过重复交接刷新窗口；窗口耗尽无可确认变更则失败收尾，保留已确认执行结果。
- [x] 交接、窗口余量和实际变更证据随执行实例保存，并在日志中区分交接声明、修改证据与任务完成。
- [x] 通过普通 ReAct 端到端场景验证探索、交接、真实补丁修改、验证和成功完成；同时覆盖窗口耗尽、空操作、脏工作目录和非 Git 工作目录，不能只证明更早失败。


## Comments

- 已实现普通 ReAct 独立交接、默认三轮修改窗口、去重业务轮计费、目标文件批次前后存在状态/内容摘要比较，以及执行实例持久化。新增 `target_files` 明确目标路径，兼容旧单路径 `target`；拒绝越界路径，符号链接/不可读状态不算确认证据。
- TDD red：真实交接场景原先以 implementation unavailable 失败；空操作窗口场景暴露缓存重复调用未消耗窗口。对应实现后均 green。
- 验证：`go test ./internal/agent -run 'TestReact(Handoff|ModificationWindow|RepeatedHandoff|ExhaustedExploration|ResumeRetainsModification)' -count=1` 通过，覆盖探索→交接→真实补丁→读取验证→完成、非 Git/既有内容、新增/删除、相同内容/抵消补丁/无关路径、重复交接、预算耗尽定位门禁、恢复沿用窗口策略。
- 任意命令用途分类与首次修改后验证的完整预算行为继续由 ticket 04/05 承担；此处不将工具成功或交接声明当作修改证据。
