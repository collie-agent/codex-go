# 07: 计划执行与多代理中的完整闭环

**What to build:** 计划中的实施步骤和承担修改任务的子代理使用完整的探索预算机制，各执行实例独立计费、交接、修改和恢复；上层调度正确处理可信失败，不把阶段切换或预算耗尽当作成功。

**Blocked by:** 06：中断恢复后继续原预算与阶段。

**Status:** ready-for-agent

- [x] 计划中的实施步骤能够取得上下文后分类，在阈值进行阶段决策，获批后调查或实施，并通过真实修改与验证完成步骤。
- [x] 不同执行步骤独立初始化预算；同一未完成步骤恢复原执行实例，沿用消耗、延期、窗口及有效策略，不因重新调度刷新。
- [x] 修改型子代理使用同样的分类、预算、阶段决策、延期、目标变化证据和修改窗口机制；分析型参与者不被强迫修改。
- [x] 多代理配置按实际节点配置名称逐字段继承基础策略，配置复制、角色选择和委派传递不丢失策略；显式零次数持续有效。
- [x] 不同委派或独立执行实例隔离，恢复同一委派延续原状态；父子及其他参与实例不能相互清零或污染计数。
- [x] 上层调度区分阶段交接、实际修改、任务完成和预算失败，保留结构化失败信息；已有工具结果未知与进程会话生命周期规则不被破坏。
- [x] 各运行入口支持已有输出协议，日志展示执行实例、任务类型、阶段、探索已用/额度、延期次数、修改窗口余量和切换、拒绝、停止原因。
- [x] 端到端覆盖计划步骤和子代理的探索、交接、真实修改、测试及完成，同时覆盖延期耗尽、恢复、独立实例隔离及失败传递。
- [x] 联合回归普通 ReAct、计划执行和多代理的完整行为，包含配置示例及使用说明；前序测试全部通过，不能仅以更早失败作为收敛证据。
