# 04: 命令修改证据与探索／验证计费

**What to build:** 普通 ReAct 使用命令修改目标代码时也能确认实际变化，并将源码调查与测试、结果核验正确区分。调用命令不能冒充修改，自称验证不能让调查免计费。

**Blocked by:** 02：实施交接到真实补丁修改。

**Status:** ready-for-agent

- [x] 命令执行前后比较实施交接目标文件的存在状态和内容，识别新增、修改和删除；兼容已有未提交改动及非 Git 工作目录。
- [x] 只读命令、测试生成物、无关文件变化、退出码为零和模型声明不满足实际目标修改条件；目标代码有可确认变化时才能满足修改窗口。
- [x] 现有命令快照版本为空不视为修改证据；读取失败、快照超限、超时或其他无法确认的情况保持未知。
- [x] 测试执行和结果核验不扣探索，仍受总预算和现有停滞机制约束；源码定位、调查修改方案以及测试失败后的源码调查扣探索。
- [x] 为行动用途与工具证据建立明确的计费对应；不能只按命令工具名称或模型阶段声明豁免调查，不增加模型审查，也不宣称自动理解任意命令的完整语义。
- [x] 混合批次包含调查仍按一轮探索计费，不能混入测试就免扣；并行调用采用明确批次证据边界，不能编造单个命令的修改归因。
- [x] 进程启动、轮询和停止的等待与结果核验不成为绕过调查计费的入口，并继续遵循进程会话的现有生命周期与停滞约束。
- [x] 命令变化证据、未知状态和计费依据随执行实例保存并进入日志，不改变工具结果未知时停止自动执行的规则。
- [x] 端到端验证命令修改、测试并完成；覆盖只读命令、产物噪声、未知快照、混合批次、并行变化，以及测试失败后重新调查仍扣探索。


## Comments

- 已按确认的三个 seam（普通 ReAct `Run`、MCP 命令／进程工具、执行实例检查点）逐轮 red → green。先复现测试和完成响应误扣、窗口内命令调查漏扣，再实现运行时用途与批次计费；另复现并修复测试产物与只读调查混合导致的假修改、未知目标快照未明确记录、历史调查结果免费回读、阈值后完成受阻及异步修改丢失启动基准。
- 目标变化使用本次工具批次前后的存在状态与内容摘要，兼容非 Git、新增／删除和既有脏内容；单目标快照上限 4 MiB，不可读、符号链接、特殊文件、超限及命令超时／取消／清理不确定均不推断成功修改。空 `command_evidence.workspace_version` 不用于证明变化。
- 用途识别采用有限、可审计的语法：`go test` 及支持的常规测试选项免探索计费；简单 `sed -i` 替换与 `apply_patch` 为修改；已有实际修改证据后，`git diff -- <精确已修改路径>` 为结果核验。全仓／历史 diff、源码读取／搜索、任意解释器／项目脚本及不支持的选项保守计为调查，不把模型的阶段声明当作豁免。此边界不宣称理解任意命令完整语义。
- 混合调查批次计一轮；调用用途、批次边界、前后快照、未知状态写入执行实例并记录日志。进程启动保留目标基准，退出／停止后才核验；跨度通过 `SinceBatch` 与完成批次表达，不编造单调用修改归因。轮询、停止和历史输出回读继承原用途，未知身份保守计费。新 MCP 连接及新交接不继承旧进程基准。
- 回归覆盖命令修改→测试→成功完成、耗尽探索后修改／验证／完成、失败测试后继续源码调查、只读／同内容／无关产物、测试产物混合批次、未知及超限快照、新增／删除、并行变化、进程用途与异步修改、历史结果用途继承；原有窗口、总预算、停滞与工具结果未知停止边界保持生效。
- 验证：`env -u CODEX_TEST_MYSQL_URL go test ./...` 通过（数据库集成测试按仓库约定跳过）；直接 `go test ./...` 的数据库相关测试因当前 MySQL 账号认证失败（1045）未通过。未修改数据库配置。
