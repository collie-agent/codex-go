# 05: 首次修改后的持续预算约束

**What to build:** 代理取得首次实际修改后，仍受原探索预算约束；后续调查达到阈值须重新选择实施、有限延期或无法完成，避免通过一次小修改解除预算。

**Blocked by:** 03：有限探索延期与拒绝后的收束；04：命令修改证据与探索／验证计费。

**Status:** ready-for-agent

- [x] 首次修改后的源码调查、后续修改方案调查继续累计同一执行实例的探索消耗，补丁或命令发生修改均不清零。
- [x] 再次达到探索阈值仍要求独立阶段决策；不能把已发生修改作为继续无限调查的豁免。
- [x] 后续延期使用同一份额度与次数，不能按文件、修改次数或阶段重新初始化；拒绝后要求实施或无法完成。
- [x] 选择继续实施时对下一次实际目标修改使用同样的有界窗口；只有确认上次实际修改后，才允许下一次修改的窗口。
- [x] 重复交接同一待实施修改不能刷新窗口；窗口内调查仍需剩余额度或获批延期，额度耗尽后只能直接修改或有界收束。
- [x] 测试和结果核验保留正常执行路径；验证失败后的源码调查继续扣探索，总预算和已有停滞机制可以提前终止。
- [x] 后续窗口、累计额度、延期次数、证据与决策状态随执行实例保存，日志能够区分首次及后续实施交接。
- [x] 端到端验证首次修改、验证失败、再次调查、阈值决策、第二次真实修改和完成；同时验证小修改后持续调查、重复交接及延期次数耗尽不能绕过上限。
