# 08: 实施阶段操作准入与有界纠正

Status: ready-for-agent

## Problem Statement

代理运行已完成实施交接，但探索预算耗尽时，修改前的工作区检查可能被当作调查并立即终止运行，导致修改窗口仍有余量却没有实际修改机会。

日志实例 `8327a7c54cdecd1ce648df3b16b14fe2` 在探索达到 12/12 后进入 implement，第一轮请求执行 git status，随即被探索额度门禁终止，日志仍显示修改窗口余量为 3。进入实施阶段或模型调用成功均不代表目标代码已经修改。

## Solution

按当前阶段和实际操作用途执行准入。探索预算耗尽时，实施阶段仍允许有限、可识别的工作区检查、修改及验证；继续调查必须具有剩余额度或获批探索延期。违规调查不执行，向模型提供纠正机会，并消耗修改窗口，避免一次误选操作提前终止，也避免无限重试。

## User Stories

1. As an 代理使用者, I want 实施交接后能够检查工作区状态, so that 代理可以了解既有改动后安全修改。
2. As an 代理使用者, I want 探索额度耗尽后仍能执行补丁, so that 已有证据足够时可以完成任务。
3. As an 代理使用者, I want 修改后能够运行测试, so that 实际变更得到验证。
4. As an 代理使用者, I want 调查受到原探索预算限制, so that 实施阶段不会变成免费探索。
5. As an 代理使用者, I want 错误选择调查操作后得到纠正机会, so that 尚有修改窗口时可以继续实施。
6. As an 代理使用者, I want 连续违规或只检查不修改最终停止, so that 代理不会无限空转。
7. As an 代理使用者, I want 具体信息缺口可通过现有延期协议处理, so that 必要调查有明确额度。
8. As an 代理使用者, I want 只读检查不被算作修改成功, so that 任务进度可信。
9. As an 代理使用者, I want 既有未提交改动不被算成本次修改, so that 代理不会虚报实施结果。
10. As an 代理使用者, I want 混合命令不能绕过预算, so that 调查约束在批量调用时仍然有效。
11. As an 代理使用者, I want 恢复后保留剩余窗口和调查消耗, so that 恢复不会刷新额度。
12. As an 维护者, I want 日志区分操作拒绝、纠正和运行结束, so that 能判断代理为何未完成修改。
13. As an 维护者, I want 未知命令采用保守分类, so that 模型不能仅靠声明验证用途取得豁免。
14. As an 代理使用者, I want 未完成时准确报告实际变更和验证结果, so that 后续工作有可靠依据。

## Implementation Decisions

- 复用现有 ReAct 运行时、操作用途分类、批次计费、实施交接和修改证据机制，不新增独立预算系统或模型审查。
- 先判断阶段，再判断用途与额度。实施阶段探索额度为零本身不是整个运行的停止条件。
- 将语法明确的 git status 视为工作区检查；支持的参数采用有限白名单，未知参数、复合命令和脚本保守视为调查。工作区检查不扣探索额度，也不能证明目标修改。
- 不普遍豁免 git diff。保留现有已确认目标变更的精确路径结果核验规则；全仓、历史或无法识别的 diff 继续按调查处理。
- 修改与既有可识别验证操作沿用现有分类。命令实际用途由工具参数和可审计语法判断，不仅依据工具名或模型声明。
- 批次含调查时沿用调查优先规则；额度不足则整批拒绝，不执行其中的修改或验证，避免部分执行造成证据歧义。
- 修改窗口内，每个普通业务决策轮至多扣一轮；工作区检查和被拒绝的调查轮均计入。拒绝轮不扣探索额度、不生成已执行工具记录，应保存真实拒绝反馈及窗口变化。
- 明确失败的修改操作是否退还窗口沿用当前独立结算规则，本修正不顺带重定义；策略拒绝不属于已执行工具明确失败，不退还窗口。
- 违规调查且窗口尚有余量时，反馈拒绝原因、可用操作和剩余窗口，继续下一业务轮。窗口耗尽仍无可确认目标变更时失败收尾；不额外赠送纠正额度。
- 允许通过现有阶段决策协议申请探索延期，沿用必要字段、次数、总预算、持久化和不刷新同一修改窗口的规则；不得把申请延期变成隐式免费调查。
- 实际目标变更仍由工具批次前后证据确认，工作区检查、退出码为零、已有脏文件和模型声明不算实施完成。确认后沿用现有后续调查与验证流程。
- 状态变化和拒绝反馈在继续模型或工具执行前持久化。恢复保留同一执行实例的有效策略、消耗、窗口与拒绝上下文。
- 总决策预算、停滞、工具结果未知和保存失败边界继续有效；这些条件仍可提前终止运行。
- 日志记录执行实例、阶段、操作用途、是否准入、拒绝原因、探索额度和窗口扣减结果。关键准入和结算处添加解释约束目的的注释。

## Testing Decisions

- 用户已确认复用现有 ReAct 运行入口：模拟模型响应、临时工作目录和真实工具执行，主要断言结果状态、文件内容、工具实际执行情况及恢复后的可见行为；避免仅断言内部函数分支。
- 沿用现有实施交接真实补丁、命令用途计费和修改窗口恢复测试的组织方式；仅在命令语法边界补充用途分类表驱动测试，不引入新的生产测试接口。
- 主成功场景：探索耗尽，实施交接，git status，真实补丁，测试或合法结果核验，最终完成。确认检查不产生修改证据，补丁才产生真实变更。
- 有界纠正场景：零探索额度下请求调查，确认工具未执行，下一轮改为补丁并成功；连续请求调查或只做检查则在窗口耗尽后失败。
- 混合批次场景：工作区检查或补丁与调查混合，额度不足时整批不执行；有额度时沿用单批次一次调查计费。
- 分类边界场景：支持的 git status 形式、未知选项、复合命令、全仓 diff 和精确目标结果核验；模型声明不改变分类。
- 恢复场景：检查后或拒绝后保存并恢复，窗口和探索额度不重置，拒绝反馈仍可供后续决策使用；不重放已执行调用。
- 保留现有失败修改结算、真实净变更、非 Git 工作目录、保存失败、未知工具结果与总预算回归覆盖。非 Git 下检查失败不应被误报为修改成功。
- 验收必须包括成功完成链路，不能只证明拒绝或更早失败。测试执行的本规格工作不包含生产代码实现。

## Out of Scope

- 增加默认探索额度、修改窗口或总预算。
- 理解任意 shell 命令语义、豁免所有只读操作，或信任模型自报用途。
- 修改工具权限、命令沙箱、任务完成标准或未知工具结果恢复规则。
- 重写既有明确失败工具的计费退款策略，新增可配置的工作区检查预算。
- 本次直接实现生产代码或拆分新的实现工单集合。

## Further Notes

本规格是既有探索预算规格的补充，细化实施阶段准入与纠正行为。遵守 ADR-0007：运行时强制预算、实施交接不等于实际修改、恢复不刷新额度；新增的有界纠正不会授予免费调查。
