# 01: 探索阈值、延后分类与阶段决策

**What to build:** 普通 ReAct 即使持续获得新证据，也会在配置的探索阈值处停下调查，要求模型在取得上下文后明确任务类型，并提交可校验的阶段决策。无法继续时有界失败，保留可信进度。实施和延期的具体执行分别由 02、03 完成。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 初始探索额度默认 12 轮，按模型决策轮次扣费；一轮多个工具计一轮，持续新证据、重复调用或混合批次均不能清零或绕过消耗。
- [ ] 不强制第一轮分类；允许取得上下文后分类，最迟在初始额度耗尽时分类。修改任务追溯计入分类前探索，分析任务说明依据后继续且不要求修改。
- [ ] 不能仅改称分析来逃避已有修改目标；查明无须改动时，必须提供具体证据才能正常完成。
- [ ] 运行时提供独立的实施、申请延期、无法完成决策契约，并校验各分支必要字段；不能把任务完成状态当作阶段切换，不要求内部思维过程。
- [ ] 阶段决策校验并保存后，下一轮才执行工具。混入决策响应的工具不执行，无有效决策时不能继续普通探索。
- [ ] 无效决策默认允许纠正一次，仍无效则失败；阶段决策和纠错消耗总预算，不占批准后的探索额度或修改窗口。
- [ ] 初始额度和决策纠错次数可在配置文件设置，基础代理配置提供默认值，代理独立配置逐字段覆盖；省略与显式零次纠错区分，非法值启动时报错。
- [ ] 状态归属于执行实例，首次保存有效策略；决策前保存消耗，阶段切换在继续执行前保存，保存失败不能放行工具。新增状态具备基本序列化与恢复能力，配置改变不刷新额度。
- [ ] 无法完成、总预算耗尽或现有停滞机制提前终止时，沿用有界收尾，保留已确认变更、验证结果、未完成项和原因；不自动回滚，不编造成功。
- [ ] 日志包含执行实例、任务类型、阶段、探索消耗和阈值、切换及停止原因。适配现有支持的输出协议；通过真实 ReAct 循环验证阈值、分析豁免、纠错及禁止执行混入工具。
