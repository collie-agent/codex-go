# 05: 按参考语义应用多文件补丁

**What to build:** MCP 客户端向启动工作目录提交 unified diff，新增、修改或删除多个文件；匹配行为与 atom-mcp 一致，失败时清楚说明是否已有文件被修改。

**Blocked by:** 01 — 启动 MCP 服务并分页读取工作目录文件。

**Status:** ready-for-agent

- [ ] 在注册函数和 stdio 服务中提供 apply_patch，仅接受必填 patch，无工具级 cwd，所有路径以启动工作目录为基准。
- [ ] 用 Go 移植 atom-mcp 的 unified diff 解析规则：多文件、多块、git 前缀和前导行、/dev/null、无末尾换行标记、按实际内容重算块行数和参考实现的空白上下文规则。
- [ ] 支持新增、修改、删除，不支持重命名；新目标不得已存在，修改和删除目标必须存在且为 UTF-8 非二进制普通文件。
- [ ] 拒绝绝对路径、越界路径、目录目标和符号链接目标，保持参考实现的路径语义。
- [ ] 按参考 ADR 顺序尝试精确匹配、忽略行尾空白、忽略首尾空白、有限标点归一化；从单调向前的游标寻找匹配，容忍过时行号。
- [ ] 匹配容差只用于定位；写入内容严格来自补丁的新侧文本，不增加通用 Unicode 归一化或全角转换。
- [ ] 所有路径、目标和补丁块验证成功后才开始写入；解析、路径或匹配失败时任何文件均不修改。
- [ ] 使用临时文件替换修改或新增目标，必要时创建新增目标的父目录；写入阶段失败不回滚已完成的操作。
- [ ] 成功返回相对工作目录的 affected 路径；失败保留 1201–1206 错误码，写入失败、超时或取消时报告已完成和失败的路径。
- [ ] 复用统一结构化结果、可读文本和完整响应 1 MiB 上限；通过统一超时和请求取消控制执行。
- [ ] 通过 MCP 请求验证多文件新增/修改/删除、各种参考解析和匹配规则、无末尾换行、越界与链接拒绝、预检查无修改，以及写入失败或取消时的部分完成报告。
