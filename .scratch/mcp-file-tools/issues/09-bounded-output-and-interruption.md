# 09: 完善大输出、失败和中断的执行结果

**What to build:** 内部调用方在命令产生大量输出、失败、超时或被取消时，仍能及时收到有界且可区分的结果和已捕获输出；后台子进程或其持有的输出管道不能让调用挂起或跨调用存活。

**Blocked by:** 07：在隔离工作区执行系统命令。

Status: ready-for-agent

父任务：[06：新增基于 bwrap 的内部命令执行器](06-bwrap-command-executor.md)。依据：[完整规格](../spec.md)中的“新增命令 sandbox”及[安全边界 ADR](../../../docs/adr/0002-command-sandbox-boundary.md)。前置任务：[07](07-isolated-system-commands.md)；本任务不依赖额外运行时目录支持。

- [x] 标准输出和标准错误分别返回，二者合计最多保留 1 MiB；达到上限后继续排空并丢弃超出数据，不因管道写满而挂起，不无限增长捕获缓冲区。
- [x] 实际丢弃输出时返回明确截断标记；没有丢弃输出时不误报截断。该上限适用于内部执行结果，不套用 MCP 响应分页或双份 JSON 计费规则。
- [x] 成功和普通非零退出均返回退出码及两路输出；普通非零退出与 sandbox 启动失败可区分，不能把 bwrap 自身失败误报为命令结果。
- [x] 参数错误、sandbox 启动失败、超时及 context 取消具有可区分的错误结果；已有输出在错误时仍可供调用方读取。
- [x] 标准输入始终为 EOF，不引入交互输入、终端或跨调用存活的后台任务。
- [x] 默认 30 秒超时和上游 context 取消都能终止执行并完成回收；取消后不能留下继续修改 Workspace 的子进程。
- [x] 入口正常退出但后台子进程仍运行或持有输出管道时，调用仍能结束并清理全部子进程；不以只杀入口或仅限制等待时间替代进程树清理。
- [x] 分别验证同时大量写入两路输出、非零退出、输出后超时、输出后取消、入口退出后子进程持有管道的行为，确认返回结果、输出上限和残留进程满足契约。
- [x] 重复调用具有独立的输出和生命周期状态，不遗留文件描述符、等待任务或 sandbox 临时状态。
- [x] 在共享输出预算、截断后排空、错误分类及进程树回收的关键位置添加注释；不扩展 CPU、内存、进程数或磁盘配额范围。

## Comments

- 已按确认的 `Execute` 公共 seam 增加 `exec_lifecycle_test.go`，覆盖双路输出共享 1 MiB 预算、普通非零退出、超时与取消的输出保留及后续写入回收、入口退出后后代持有输出管道等行为。
- `Execute` 将 bwrap 的完成状态作为生命周期真相；入口已完成但后代短暂持有输出管道导致 `os/exec` 返回 `ErrWaitDelay` 时，仍返回普通命令结果，避免把已完成调用误报为 sandbox 启动失败。
- 红灯证据：完成状态以外的 `*exec.ExitError` 曾被错误返回为 nil；修复后仅 `completed && (ExitError 或 ErrWaitDelay)` 视为普通命令结果。通过删除已配置 runtime 目录，再执行 `python3`，验证 `errors.Is(err, ErrSandboxStartup)` 成立。
- 绿色验证：`go test ./internal/mcp -run '^TestExecute' -count=1 -timeout=45s` 通过（31.626s），覆盖真实默认 30 秒超时；`git diff --check` 通过。
