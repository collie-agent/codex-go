# 02: 持久化完整输出并支持历史补读

**What to build:** 用户无论是否在线，都能在重新打开会话后读取完整输出历史；实时推送中断或临时流过期后，消费者能够按游标补读、排序并去重。

**Blocked by:** 01: 实时输出携带代理参与实例归属。

**Status:** resolved

- [x] 输出生产链路先成功持久化，再推送实时流；没有 SSE 连接时仍记录完整事件及归属元数据。
- [x] 每条事件分配稳定 ID 和运行内顺序号；并发生产保持顺序号唯一，历史读取按顺序返回，推送和补读保留同一事件身份。
- [x] 提供历史读取与游标补读能力，包含正文增量、工具交互及通用事件元数据；临时流过期后仍可读取。
- [x] 历史记录可关联所属会话与代理运行，随会话保留，不依赖临时输出流有效期或 SSE 消费过程。
- [x] 持久化失败向执行链返回错误并停止当前执行，不发布尚未成功记录的事件。
- [x] 已持久化事件在实时推送失败后仍可补读；失败不改变事件身份或制造重复历史记录。
- [x] 测试覆盖无人在线、并发排序、临时流过期、持久化失败及推送失败后的补读；同步更新消费协议说明。

范围不包含 TUI 实现，不迁移历史数据；生命周期事件由 03 定义，04 验证其历史回放。

## Comments

实现了生产端先持久化、运行内稳定序号与事件 ID、Redis/SSE 身份传播和会话运行历史游标接口。持久化或推送错误会停止执行，已保存事件仍可补读；队列终态也先持久化。历史按运行关联会话保留。

验证：输出故障阻止推送、真实 MySQL 并发序号和游标、运行期间持久化故障中止、实时发送失败后补读，以及无人连接并删除 Redis 临时流后的 HTTP 补读。按逐条 red→green 实现主要功能；全库结果见最终交付。

最终验证：使用独立 MySQL 测试库执行 `go test -p 1 -count=1 ./...`；仅既有临时库创建测试因测试账号权限失败，补齐权限后单独重跑该测试通过，其余包全部通过。`go test -race ./internal/agent ./internal/provider ./internal/server -count=1` 通过，`git diff --check` 通过。
