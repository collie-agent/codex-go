# 04: 恢复运行时延续身份并重建完整代理视图

**What to build:** 用户重新打开会话或恢复未完成的代理运行时，消费者能够从历史与实时事件重建一致的代理层级、状态和完整输出，不将恢复后的同一代理误认为新子代理。

**Blocked by:** 02: 持久化完整输出并支持历史补读；03: 通过生命周期事件展示代理状态。

**Status:** resolved

- [x] 代理参与实例身份与父关系跨检查点恢复保持稳定；不同独立委派仍保持不同身份。
- [x] 恢复延续原代理运行及参与实例，生命周期可重新进入运行中，新增事件延续运行内顺序号且不复用已有事件 ID。
- [x] 已完成节点无需重新执行或重发模型输出，即可通过历史记录恢复其层级、状态和内容。
- [x] 主动中断的运行不能恢复；缺失终态的节点不会在回放时被推断为成功。
- [x] 历史读取与实时订阅交接支持稳定游标与事件身份，消费者可补齐交接期间的事件并去重，不遗漏输出。
- [x] 验证同名并发子代理、嵌套委派、多轮执行与恢复后的层级和输出一致；无客户端在线及临时流过期后同样可重建。
- [x] 通过集成测试和消费协议示例验证完整回放及实时接续，不要求实现 TUI 页面。


## Comments

已实现恢复前拒绝主动中断运行；新增运行级持久 SSE `/conversations/{conv_id}/runs/{run_id}/events/stream`，以运行内序号统一历史回放与新增事件接续，支持 `after_sequence`、`Last-Event-ID` 和稳定事件身份，不依赖 Redis 临时流。消费协议和视图重建示例见 `docs/output-replay.md`。
