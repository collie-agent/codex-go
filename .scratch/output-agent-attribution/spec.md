# 输出事件的代理归属

## 已确认的目标

- TUI 展示代理父子层级、运行状态，并支持切换查看各代理的完整输出。
- 重新打开会话后需要恢复代理层级和历史输出。
- 本次先确定事件契约，TUI 实现留待后续工作。
- 每次独立委派对应独立的代理参与实例；名称仅用于展示，父关系指向具体参与实例。主代理也有明确身份。
- 同一委派内的多轮执行及恢复沿用同一参与实例身份。
- 历史记录随会话保留，包含层级、状态、正文增量与工具交互；不能仅依赖临时输出流的有效期。

## 事件契约

- 每条新事件携带 `run_id`，现有 `task_id` 继续用于输出流路由，两者不得混用。
- 代理产生的事件携带 `agent_instance_id`、`parent_agent_instance_id`、`agent_name`；主代理的父身份为空，整个运行的汇总事件允许没有代理身份。
- 新元数据贯穿 OutputEvent、Redis 和 SSE 链路。保留 `type/delta` 含义，不要求兼容历史数据。
- 多代理模式通过 `agent_switch` 表达委派及结果交回，消息体包含 `src_agent_name`、`dst_agent_name`；归属字段指向发起切换的代理参与实例。并发分支各自发出事件。
- 生命周期事件表达待执行、运行中、完成、失败、主动中断；恢复时原实例可重新进入运行中。主动中断保持现有不可恢复语义。
- 缺失终态不代表完成，进程突然消失不能被推断为成功结束。
- 每条事件具有稳定 ID 和运行内顺序号，用于补读、排序和去重。

## 历史与故障处理

- 输出生产链路先成功持久化事件，再推送实时流；完整历史不依赖 SSE 连接是否在线。
- 持久化失败时返回错误并停止当前执行，不继续产生无法保证记录的输出。
- 实时推送失败后，客户端能够从历史记录补读。
- 历史记录与会话关联并随会话保留，提供历史读取能力。

## 实现范围与验收场景

后续实现覆盖代理身份传播、生命周期事件、输出协议、Redis/SSE 传输、持久化和历史读取；TUI 界面本身不在本次范围内。

- 两个同名子代理并发执行时，输出分别归属两个参与实例。
- 嵌套委派指向具体父参与实例，同一委派多轮执行不拆成多个界面条目。
- 恢复延续身份，已完成节点无需重新执行即可从历史恢复展示。
- 无 SSE 客户端在线时仍保存完整历史，临时流过期后仍可读取。
- 持久化失败返回执行错误；实时推送失败后补读不重复展示事件。
- 运行汇总事件不会被错误归属给某个子代理。

所有分项设计选择均已确认，等待用户确认整体理解后结束设计访谈；尚未开始代码实现。
