# 02: 按 YAML 工具允许列表执行完整任务

**What to build:** 用户通过 YAML 明确允许工具后，ReAct 代理只使用这些工具在指定工作目录中执行任务，将工具结果用于后续决策，最后输出答案或失败原因。

**Blocked by:** 01 — 通过 YAML 运行无工具的 ReAct 任务。

**Status:** resolved

- [x] YAML 中允许的工具传递到实际模型请求；模型只能看到允许列表中的工具，列表省略或为空时不暴露任何工具。
- [x] 执行端拒绝未允许的工具调用，不执行其操作，即使模型返回了此类调用。
- [x] 接通内部 MCP 工具执行、结果回传和后续 ReAct 决策，完成至少一个依赖工具结果的端到端任务。
- [x] 支持现有工具名称 `read_file`、`list_dir`、`glob`、`grep`、`apply_patch`；沿用现有工具行为及补丁匹配决策，不改变补丁语义。
- [x] 工具操作使用 CLI 指定的工作目录，遵守现有访问范围；工具命令超时使用 `--timeout`，不从 YAML 读取。
- [x] 工具错误按现有 ReAct 上下文机制反馈给后续决策；最终成功、失败与固定 100 轮限制沿用票据 01 的结果及退出码约定。
- [x] 通过可控模型响应和临时工作目录验证允许工具执行、未允许工具被拒绝、空列表禁用全部工具，以及结果回传、工作目录边界和工具超时。
- [x] 保留既有用户改动，关键行为添加注释。

## Answer

已将 YAML 的 `allow_tools` 接入 MCP 注册与 Responses 工具列表：允许列表只暴露对应工具，空列表不暴露工具；执行端仍对模型返回的越权调用做拒绝。CLI 端到端测试覆盖 `read_file` 在指定工作目录执行、结果进入下一轮模型请求、越权调用和空列表场景。既有工具实现、工作目录边界、超时和固定 100 轮语义保持不变。
