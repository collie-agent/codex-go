# 代理参与实例生命周期

实时输出和历史中使用 `agent_lifecycle` 事件，`data`（SSE 中为 JSON 字符串 `delta`）为 `{"status":"pending"}` 等状态对象。事件的 `run_id`、`agent_instance_id`、`parent_agent_instance_id` 和 `agent_name` 与该实例产生的其他输出一致；主实例的父身份为空。创建委派时即发送 `pending`，不需要等待正文，因此客户端可先建立代理层级。

状态及允许的变化：

- `pending`：已创建但尚未获得执行机会，可进入 `running`、`failed` 或 `interrupted`。
- `running`：正在执行或等待所委派的工作，可进入 `completed`、`failed` 或 `interrupted`。
- `completed`：该参与实例成功完成。
- `failed`：业务结果失败、执行出错或因同级执行错误被取消；同级取消不表示用户主动中断。
- `interrupted`：用户主动中断整个运行，不能恢复该运行。

可恢复的失败运行重新开始时，原参与实例使用相同身份再次进入 `pending` 和 `running`；已经完成的实例不会因恢复而重新执行。一次委派的多轮模型调用属于同一个参与实例，不因轮次变化产生终态。恢复跳过已完成的委派时，会根据已确认的检查点为整个已完成子树补记终态，以修复检查点提交后终态写入失败或进程退出造成的缺口；同一实例可能收到重复的终态观察，客户端按实例身份更新状态，正文和工具操作不会重放。客户端应按事件顺序处理，不能把缺少终态视为完成：进程异常退出或输出无法写入时可能没有终态。

`task_completed` 和 `task_interrupted` 表示整个队列任务的结束，与单个参与实例生命周期分别判断。`failed` 不必然表示整个任务失败，例如父代理可以处理子代理的业务失败并继续执行。
