# 重复失败命令保护

ReAct 通过 `exec` 返回的 `exit_code` 和 `error_kind` 识别失败；普通非零退出即使 MCP 状态为 success，也属于命令失败。工具名和规范化 JSON 参数共同确定命令身份。

同一命令失败后，没有中间状态变更调用时，下一次调用被拦截。模型收到配对的历史工具结果，以及检查错误、修复源码、依赖或环境后重试的提示。成功命令仍可重复执行。

超时及包含临时网络错误特征的失败允许一次重试；错误文本中的时间戳或尝试编号变化不会重置次数。连续三批只有被拦截的调用时，执行沿用现有重复调用终止机制，避免模型持续空转。

状态变更采用保守的工具调用边界：`apply_patch`、其他 `exec` 命令以及进程会话操作使已有失败记录失效，失败的写入也可能留下修改。并行批次整体处理；新产生的失败会作为后续判断依据。普通文件读取不会解除保护。

恢复时从当前执行实例已保存的工具历史重建保护。该机制不扫描工作区内容，也不自动检测用户在工具调用之外修改文件或外部服务恢复；需要经过可能改变状态的工具操作后重新验证。网络错误识别基于诊断文本特征，不能覆盖所有工具的错误格式。
